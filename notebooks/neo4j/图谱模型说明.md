# Neo4j 人才统一图谱 POC：模型说明

## 1. 用途与边界

本 POC 用于演示以人员为中心，连接工作经历、项目实践和个人学习信息的图数据效果。重点是 Neo4j Browser 中的关系可视化，不包含简历文件解析、接口同步、权限、生产部署或真实个人数据。

所有人员、企业、项目、课程和证书名称均为虚构示例。每类实体使用稳定业务编码作为唯一标识，便于后续替换为客户的结构化数据。

## 2. 执行顺序

在 Neo4j 5 的目标数据库中，依次执行下列文件：

1. `01_schema.cypher`：创建唯一约束及查询索引；不删除任何已有数据。
2. `02_seed_demo_data.cypher`：写入 POC 数据；所有节点和关系均采用 `MERGE`，可重复执行而不产生重复数据。
3. `03_demo_queries.cypher`：在 Neo4j Browser 中按查询块执行并查看图形结果。

> 若目标库中已存在使用相同编码的数据，脚本会更新这些节点和关系的示例属性。因此建议在专用 POC 数据库运行。

## 3. 节点模型

| 标签 | 唯一编码 | 关键属性 | 说明 |
| --- | --- | --- | --- |
| `Person` | `personId` | `name`、`city`、`yearsOfExperience`、`summary` | 人才统一入口。 |
| `WorkExperience` | `workExperienceId` | `startDate`、`endDate`、`isCurrent`、`description` | 一段独立任职经历。 |
| `Company` | `companyId` | `name`、`scale` | 可跨候选人复用的企业实体。 |
| `Position` | `positionId` | `name`、`category` | 标准岗位，可同时承载任职岗位和目标岗位。 |
| `Industry` | `industryId` | `name` | 企业所属行业。 |
| `Region` | `regionId` | `name`、`level` | 企业所在区域。 |
| `Project` | `projectId` | `name`、`startDate`、`endDate`、`description` | 工作经历中的项目实践。 |
| `Skill` | `skillId` | `name`、`category` | 跨人员、项目、岗位和课程共享的技能。 |
| `Major` | `majorId` | `name` | 人员所学专业。 |
| `LearningRecord` | `learningRecordId` | `startDate`、`endDate`、`status`、`score` | 一次课程学习事实。 |
| `Course` | `courseId` | `name`、`provider` | 标准课程。 |
| `LearningMethod` | `methodId` | `name` | 线上自学、集中培训、项目实践等方式。 |
| `Certificate` | `certificateId` | `name`、`issuer` | 学习记录产生的证书或认证。 |

## 4. 关系模型

| 关系 | 起点 → 终点 | 属性 | 含义 |
| --- | --- | --- | --- |
| `HAS_WORK_EXPERIENCE` | `Person → WorkExperience` | — | 人员拥有一段任职经历。 |
| `AT_COMPANY` | `WorkExperience → Company` | — | 任职经历所属企业。 |
| `AS_POSITION` | `WorkExperience → Position` | — | 任职经历中的岗位。 |
| `PARTICIPATED_IN` | `WorkExperience → Project` | `role` | 在该经历中承担的项目角色。 |
| `IN_INDUSTRY` | `Company → Industry` | — | 企业所属行业。 |
| `LOCATED_IN` | `Company → Region` | — | 企业所在区域。 |
| `USES_SKILL` | `Project → Skill` | — | 项目实践使用的技能。 |
| `HAS_SKILL` | `Person → Skill` | `proficiencyLevel`、`acquiredDate`、`source` | 人员的技能掌握事实；等级为 1–5。 |
| `TARGETS` | `Person → Position` | — | 人员目标岗位。 |
| `REQUIRES_SKILL` | `Position → Skill` | `minimumLevel` | 岗位所需技能及最低等级。 |
| `MAJORED_IN` | `Person → Major` | — | 人员专业背景。 |
| `HAS_LEARNING_RECORD` | `Person → LearningRecord` | — | 人员的一次学习记录。 |
| `LEARNED_COURSE` | `LearningRecord → Course` | — | 学习记录对应课程。 |
| `LEARNED_BY` | `LearningRecord → LearningMethod` | — | 采用的学习方式。 |
| `RELATED_TO_SKILL` | `LearningRecord → Skill` | — | 学习记录直接关联的技能。 |
| `COVERS_SKILL` | `Course → Skill` | `coverageLevel` | 课程覆盖技能的程度，等级为 1–4。 |
| `EARNED` | `LearningRecord → Certificate` | — | 学习完成后获得的认证。 |

## 5. 推荐演示方式

- 先运行 `PERSON_FULL_GRAPH`，以人员“林澈”为入口查看工作和学习如何汇聚到一个人才画像。
- 再运行 `PERSON_PROJECT_SKILL_POSITION_GRAPH`，演示人员、项目、技能、任职岗位之间的关系。
- 运行 `POSITION_CANDIDATE_EVIDENCE`，以“AI应用工程师”为例，展示岗位要求与候选人项目/课程技能证据。
- 运行 `COURSE_SKILL_POSITION_GRAPH`，展示课程如何覆盖岗位所需技能，为后续课程推荐或能力差距分析预留扩展点。

Neo4j Browser 可在结果图中双击节点展开邻居；建议先限制在单个候选人或单个岗位范围内，以获得更清晰的演示效果。

## 6. 后续接入真实数据时的替换规则

1. 将 `PER`、`COM`、`POS`、`SK` 等示例编码替换为客户系统中的稳定主键或标准编码。
2. 将简历解析结果写入 `WorkExperience`、`Project`、`Skill` 等事实节点和关系；不要用候选人的姓名作为唯一键。
3. 将学习平台数据写入 `LearningRecord`，并通过课程、技能、证书字典与统一图谱关联。
4. 由客户确认岗位、技能、行业、课程字典及同义词归并规则后，再扩展标准化和实体消歧逻辑。
